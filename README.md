# SILVA EDIT

動画・音声ファイルを Chrome のサイドパネルで手早く編集できる拡張機能です。  
トリミング、クロップ、回転/反転、再生速度変更、音声抽出、フレーム保存に対応しています。

**[Chrome ウェブストアからインストール](https://chromewebstore.google.com/detail/silva-edit/jhoopmdknkooacpocbapgmmmgladkfbc)**

## 主な機能

- トリミング（iOS風シークバー / 数値入力 双方向同期）
- クロップ（8点ハンドル + アスペクト比固定 1:1 / 4:3 / 16:9 / 9:16、Shiftで一時固定）
- 回転（90°単位）・左右反転・上下反転
- 再生速度変更（0.25x〜4x）
- 再生トランスポート（常時表示のシークバー / トリム範囲表示 / 区間を再生）
- 繰り返し書き出し（同じクリップを ×1〜×3 回つなげた1本の動画として保存）
- 動画音量調整（0〜200%）
- 音を両耳にする（左だけ/右だけの音を左右どちらからも聞こえるようにする）
- MP4 書き出し（書き出し方式を「高品質 / 高速」から選択）
- MP3 書き出し（高: 320kbps / 中: 192kbps）
- 書き出し中の前面進捗表示（FFmpeg の実進捗をバーと％で表示）
- 現在フレーム保存（PNG）
- クロップ後フレーム保存（PNG）
- **一括分割モード**: マーカーで複数クリップに分割し、まとめて MP4 / MP3 / 先頭フレーム を一括書き出し
- **一括処理モード**: 複数動画から同じ秒の画像をまとめて保存、複数動画/音声の音を両耳で聞けるように一括保存
- UI テーマ切替（ゆるシルバ / キリシルバ）

## 対応フォーマット

### 入力

- 動画: `mp4`, `webm`, `mov`, `ogv`, `mkv`（`video/*`）
- 音声: `mp3`, `wav`, `m4a`, `aac`, `ogg`, `flac`, `opus`（`audio/*`）

### 出力

- 編集動画: `mp4`
- 音声のみ: `mp3`
- フレーム画像: `png`

## インストール（ローカル）

1. `chrome://extensions` を開く
2. 「デベロッパーモード」を ON
3. 「パッケージ化されていない拡張機能を読み込む」でこのフォルダを選択
4. ツールバーの SILVA EDIT アイコンをクリックしてサイドパネルを開く

このフォルダを読み込むと、表示名は `SILVA EDIT-dev` になる（開発用）。配布用（表示名 `SILVA EDIT`）の zip は `python tools/build-zip.py` で作る。`dist/SILVA-EDIT-<version>-webstore.zip` が生成される。

## 使い方

### 通常編集モード

1. 動画/音声をドラッグ&ドロップ（またはクリック選択）
2. 必要に応じて開始・終了時間（シークバー or 数値入力）、クロップ範囲、速度、回転/反転、繰り返し回数を調整
3. 以下のいずれかを実行
   - `編集動画書き出し`（MP4）
   - `音声のみ保存（MP3）`
   - `現在フレームを保存` / `切り取ったフレームを保存`（PNG）

動画の下には常時表示のトランスポート（再生/一時停止、シークバー、現在/全体時間、`区間を再生`）が出る。シークバーの背景にはトリム範囲が帯で表示され、サムネイル帯のクリックでもシークする。入力欄にフォーカスが無いときの `Space` でも再生/一時停止する。

`繰り返し`（×1〜×3）は、通常編集モードの `編集動画書き出し` にだけ付く。同じクリップを N 回つなげた1本の動画として書き出し、ファイル名の末尾に `-x2` / `-x3` が付く。音声のみ保存（MP3）、一括分割、一括処理には付かない。

### 書き出し方式（MP4）

動画を読み込むと `書き出し方式` のセレクトが出ます。

- `高品質`（既定）: 常に再エンコードします。カット位置が指定どおり正確です
- `高速`: 再エンコードを飛ばしてそのまま切り出します。画質は元データのまま無劣化で、処理は一瞬で終わります

`高速` が実際に使われるのは、クロップ・回転/反転・再生速度・音量・チャンネル操作をいずれも行っていない場合だけです。ひとつでも変更があると自動的に `高品質` で書き出します（セレクトの下に、そのときどちらになるか表示されます）。

`高速` はカット位置が最寄りのキーフレームに寄るため、指定した開始時間より少し前から始まることがあります。フレーム単位で正確に切りたい場合は `高品質` を選んでください。また、MP4 にそのまま格納できないコーデック（WebM の VP8/VP9 など）が入力の場合は、自動的に再エンコードへ切り替わります。

### 一括分割モード

1. ヘッダの `一括分割` ボタンでモード切替
2. タイムラインをクリックで分割線を追加、または `現在位置で分割` ボタン、もしくは `N秒ごとに自動分割`
3. 分割線をドラッグで微調整、リスト内の数値で精密調整
4. 各クリップ行の `MP4` / `MP3` で個別書き出し、または下部の `分割を一括書き出し` で全クリップを連続出力
5. 各クリップは Chrome のダウンロードフォルダに順次保存されます。保存先を変更したい場合は Chrome の設定（`chrome://settings/downloads`）で指定してください
6. 初回は「複数のファイルをダウンロードしようとしています」プロンプトが出る場合があります。「許可」を選択してください

### 一括処理モード

1. ヘッダの `一括処理` ボタンでモード切替
2. `まとめて画像保存` は枠内に複数動画をドラッグ&ドロップ、またはクリックで選び、秒位置を指定して `一括保存`
3. `音を両耳にする` は枠内に複数ファイルをドラッグ&ドロップ、またはクリックで選び、元にする音（左 or 右）を選んで `一括保存`
4. `まとめて画像保存` は FFmpeg を使わず、動画を1本ずつ読み込んで PNG 化します
5. `音を両耳にする` は FFmpeg WASM で1ファイルずつ処理し、動画は MP4、音声は MP3 として保存します

## 処理エンジン

### 動画書き出し（高品質）: WebCodecs

`高品質` の MP4 書き出しは、映像を WebCodecs の `VideoEncoder`（H.264、ハードウェアエンコーダ優先）で再エンコードします。デコード、Canvas でのクロップ・回転・反転・速度変更、エンコード、MP4 への格納を `webcodecs-export.js` が行い、コンテナの読み書きには mediabunny を使います。

音声は、音量・チャンネル・速度のいずれも変更していない場合は AAC パケットをそのまま MP4 に格納します（AAC 以外の音声は WebCodecs の `AudioEncoder` で AAC に再エンコードします）。音声に手を入れる場合は音声だけ FFmpeg WASM で処理し、映像と `-c copy` で結合します。

映像のビットレートは `幅 × 高さ × fps × 0.15` bps（1〜20 Mbps）です。実測（Chrome 153 / Windows 11 / AMD GPU、852x480 24fps 10 秒、ソースに対する SSIM）では、この設定で x264 `veryfast crf 23` と同等以上の画質になります（0.1 bpp では SSIM 0.972、x264 は 0.978、0.2 bpp では 0.986）。その代わりファイルは x264 より 1.5〜3 倍程度大きくなります。

同じ環境での書き出し時間（音声あり、10 秒クリップ、0〜10 秒を等速で書き出し）:

| 素材 | FFmpeg WASM（マルチスレッド版） | WebCodecs |
|---|---|---|
| 852x480 24fps | 3,308 ms | 877 ms |
| 1920x1080 24fps | 14,235 ms | 2,060 ms |

WebCodecs が使えない環境、H.264 エンコーダが無い環境、変換中に失敗した場合は、従来どおり FFmpeg WASM（libx264）で書き出します。`高速`（ストリームコピー）、音声抽出、フレーム保存、一括処理は FFmpeg WASM のままです。

### FFmpeg WASM

`manifest.json` で cross-origin isolation（`cross_origin_embedder_policy` / `cross_origin_opener_policy`）を有効にしているため `SharedArrayBuffer` が使え、マルチスレッド版の FFmpeg WASM で処理します。再エンコードを伴う書き出しは、シングルスレッド版と比べて実測で約 2.2 倍速くなります（8 秒 / 640x360 のクリップで 5,070ms → 2,269ms）。

`SharedArrayBuffer` が使えない環境や、マルチスレッド版の読み込みに失敗した場合は、同梱のシングルスレッド版へ自動で切り替わります。

なお `@ffmpeg/core-mt` は `-threads` を指定しないと libx264 がデッドロックするため、常に明示しています（`MT_THREAD_COUNT`）。

## 動作方針（プライバシー）

- `ffmpeg-core.wasm` を使ったローカル処理です
- 編集対象ファイルを外部サーバーへアップロードしません
- 権限は `sidePanel` のみ（`manifest.json`）

## 注意点

- 音声ファイル入力時は動画系操作（クロップ、回転/反転、動画書き出し、フレーム保存、一括分割）は無効になります
- 大きなファイルはブラウザメモリ使用量が増え、処理時間も長くなります
- 書き出し中は画面下部の進捗カードに処理名、件数、FFmpeg の実進捗％を表示します
- まとめて画像保存は一度に60件、合計8GBまで。極端に高解像度の動画はブラウザ保護のためスキップします
- 音を両耳にする処理は一度に60件、合計8GBまで。FFmpeg WASM の都合で1ファイル1.5GBを上限にしています
- 一括分割の書き出し中はサイドパネルを閉じないでください（処理が中断されます）
- 連続ダウンロード時、Chrome から「複数のファイルをダウンロードしようとしています」プロンプトが出る場合があります。初回に許可してください
- サイトではなく拡張サイドパネル上で完結するツールです

## ファイル構成

- `manifest.json`: 拡張定義（MV3 / サイドパネル）
- `background.js`: アクションクリック時のサイドパネル起動
- `panel.html`: UI レイアウト
- `panel.css`: UI スタイル
- `panel.js`: 編集ロジック（トリム/クロップ/変形/FFmpeg処理）
- `webcodecs-export.js`: WebCodecs による動画書き出し（DOM 非依存）
- `vendor/ffmpeg/`: FFmpeg WASM（シングルスレッド版・フォールバック用）
- `vendor/ffmpeg-mt/`: FFmpeg WASM（マルチスレッド版・通常はこちらを使用）
- `vendor/mediabunny/`: mediabunny（MP4/WebM の読み書き。`tools/bundle-mediabunny.sh` で IIFE 化）
- `bench/`: WebCodecs と FFmpeg の書き出し比較ページ（開発用、拡張には含めない）
- `images/`: アイコン類

## 開発メモ

- バージョン更新時は `manifest.json` の `version` を更新（`name` は `SILVA EDIT-dev` のままにする。配布 zip は `python tools/build-zip.py` が `SILVA EDIT` に書き換えて作る）
- UI 変更時は `panel.html` と `panel.css` をセットで調整
- 書き出し速度の比較は `node bench/serve.mjs` を起動し、Chrome で `http://localhost:8765/bench/` を開いて行う（COOP/COEP 付きで配信するのでマルチスレッド版 FFmpeg も動く）
- 変換ロジックの純粋関数は `node bench/transform.test.mjs` でテストする
- 反転は表示座標基準（回転してから左右/上下反転）。プレビュー（CSS / Canvas）、FFmpeg の `transpose` → `hflip`/`vflip`、WebCodecs の Canvas 描画、crop 矩形の追従（`flipCropRect`）をすべてこの順序に揃えている
- 書き出しロジックの変更は `panel.js` の FFmpeg 引数を確認
